Configuring IAM User

  1. 1 Open the AWS console, navigate to the IAM dashboard and select Users.

  2. 2 Click Add user, enter a descriptive user name, and proceed to the next step.

  3. 3 Under Permissions, attach the required policy. For read-only CloudWatch access select CloudWatchLogsReadOnlyAccess.

  4. 4 Review the configuration and click Create user to provision the account.

  5. 5 Open the newly created user by clicking its name to view details and manage credentials.

  6. 6 Go to the Security credentials tab to create programmatic access keys.

  7. 7 Click Create access key and choose the option for an application running outside AWS (programmatic access).

  8. 8 Confirm creation of the access key. AWS will generate an Access Key ID and Secret Access Key.

  9. 9 Download the credentials or copy the Access Key ID and Secret Access Key to a secure location. Treat the secret as sensitive.

  10. 10 Enter the obtained credentials into the integration form below and validate the configuration.

Configuring AWS CloudWatch

  1. 11 Create a CloudWatch Log Group. Open the CloudWatch console, choose Log management and click Create log group.

  2. 12 Name and retention. Enter the log group name utmstack and set retention to 1 day. Click Create log group.

  3. 13 Open CloudTrail and start trail creation. In the CloudTrail console click Create trail to begin configuring a new trail.

  4. 14 Configure delivery, validation and CloudWatch integration (single form). On the CloudTrail creation form set the following options as shown in the screenshot:

    • Trail name and scope: enter a descriptive name; enable Apply trail to all accounts in my organization if you require org‑wide collection.
    • S3 destination: choose Create new S3 bucket (or select an existing bucket) for raw log delivery.
    • Encryption: enable Log file SSE‑KMS and select the appropriate KMS key.
    • Log file validation: enable to ensure integrity of delivered logs (recommended).
    • CloudWatch Logs: enable delivery to CloudWatch and select Use existing log group, then enter the exact name utmstack.
    • IAM role: provide or create the role CloudTrail will assume to write to S3 and publish to CloudWatch (example: CloudTrail-UTMStack-DeliveryRole).

  5. 15 Select event types. On this screen enable the event categories required for monitoring and auditing. Follow the three sections below and match the checkboxes shown in each screenshot.

    1. Management events

    • Enable Management events and select All (or the equivalent option) to record all API activity that manages AWS resources (create, update, delete).
    • Reason: captures administrative changes and configuration actions needed for auditing and incident investigation.

    2. Data events

    • Add at least one Data event. Choose S3 and select Log all events (or All S3 object-level events) to capture object-level operations such as GetObject and PutObject.

    3. Network activity events (photo: 8.png)

    • In the Network Activities section add at least one service. For example, select ec2.amazonaws.com and enable Log all events for that service.

    After confirming these selections, click Next to continue. Ensure the options match the screenshots and cover the resources you need to audit.

  6. 16 Configure aggregation and review. On the Configure event aggregation screen accept the defaults (or adjust if required). Review all settings and click Create trail.

  7. 17 Activate the integration. After the trail is created and events are flowing to utmstack, click the button below to enable UTMStack features for this integration.
